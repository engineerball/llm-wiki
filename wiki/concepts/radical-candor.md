# Radical Candor

กรอบแนวคิดการให้ฟีดแบคของ [[kim-scott|Kim Scott]] (อดีตผู้บริหารที่ Google และ Apple) ที่มุ่งสร้างสมดุลระหว่าง **การใส่ใจคนในทีมในระดับบุคคล** กับ **ความตรงไปตรงมาในการพูดถึงปัญหา** จาก [[radical-candor-naluri-2026|บทความ Naluri (ไทย)]]

## สองแกนหลัก

1. **Care Personally (ใส่ใจในตัวบุคคล)** — สร้างความสัมพันธ์ในที่ทำงาน แสดงความเห็นอกเห็นใจ สนใจความเป็นอยู่และสุขภาพจิตของคนในทีม
2. **Challenge Directly (ท้าทายอย่างตรงไปตรงมา)** — พูดถึงปัญหาหรือจุดที่ต้องปรับปรุงอย่างชัดเจน ไม่พยายามทำให้คำพูดดูดีเกินจริงหรือหลีกเลี่ยงเรื่องที่อาจทำให้อึดอัด

Kim Scott สังเกตว่าหัวหน้าทีมส่วนใหญ่มักเอียงไปทางใดทางหนึ่ง — ใส่ใจมากแต่ไม่กล้าพูดตรง หรือพูดตรงมากแต่ไม่ใส่ใจความรู้สึก — ทั้งสองแบบล้วนทำให้ทีมพลาดโอกาสพัฒนา

## ควอแดรนต์ทั้ง 4

แผนภาพ 2 แกน (แกน X = Challenge Directly, แกน Y = Care Personally) แบ่งรูปแบบการให้ฟีดแบคออกเป็น 4 แบบ:

| | Challenge Directly สูง | Challenge Directly ต่ำ |
|---|---|---|
| **Care Personally สูง** | **Radical Candor** — ใส่ใจ + ตรงไปตรงมา → ฟีดแบคที่ดีที่สุด | **Ruinous Empathy** — ใส่ใจแต่ไม่กล้าพูดตรง → หลีกเลี่ยงความจริง |
| **Care Personally ต่ำ** | **Obnoxious Aggression** — ตรงแต่ไม่ใส่ใจความรู้สึก → ทำลายความสัมพันธ์ | **Manipulative Insincerity** — ไม่ใส่ใจและไม่ตรงไปตรงมา → ไม่จริงใจ ทำลายความไว้วางใจ |

- **Radical Candor** (ใส่ใจสูง + ตรงไปตรงมาสูง) — ฟีดแบคที่มีทั้งความเห็นใจและความชัดเจน ผู้รับเข้าใจจุดแข็ง/จุดที่ต้องปรับปรุง รู้สึกปลอดภัยที่จะรับฟังและแสดงความเห็น
- **Ruinous Empathy** (ใส่ใจสูง + ตรงไปตรงมาต่ำ) — เจตนาดีแต่หลีกเลี่ยงความจริงที่สำคัญ ผู้รับไม่รู้ว่าต้องปรับปรุงอะไร พลาดโอกาสพัฒนา
- **Obnoxious Aggression** (ใส่ใจต่ำ + ตรงไปตรงมาสูง) — ตรงและชัดเจน แต่ไม่คำนึงถึงความรู้สึก ผู้รับรู้สึกถูกโจมตี/หมดกำลังใจ
- **Manipulative Insincerity** (ใส่ใจต่ำ + ตรงไปตรงมาต่ำ) — แย่ที่สุด ไม่จริงใจและไม่ช่วยเหลือ นำไปสู่ความไม่ไว้วางใจ

## 5 ขั้นตอนการนำไปใช้

1. **สร้างความสัมพันธ์และความไว้วางใจก่อน** — ผ่าน 1-on-1 สม่ำเสมอ เข้าใจจุดแข็ง ความคาดหวัง และเป้าหมายของแต่ละคน
2. **ให้ฟีดแบคสม่ำเสมอและทันที** — ไม่รอถึงรอบประเมินประจำปี ให้เป็นกิจวัตรของการสื่อสารทุกวัน
3. **สื่อสารตรงไปตรงมาแต่รักษาความสัมพันธ์** — เริ่มด้วยการชื่นชมความพยายาม แล้วค่อยพูดถึงสิ่งที่ต้องปรับปรุง โดยไม่หลีกเลี่ยงปัญหา
4. **ส่งเสริมการแลกเปลี่ยนความเห็นแบบสองทาง** — ชวนทีมฟีดแบคกลับมาที่ตัวหัวหน้าเองด้วย เพื่อสร้างความเปิดกว้าง
5. **ใช้แผนภาพควอแดรนต์ตรวจสอบฟีดแบคก่อนพูด** — เช็คว่าสิ่งที่กำลังจะพูดอยู่ในโซน Radical Candor หรือเอียงไปทางควอแดรนต์อื่น

## เทคนิคเสริม

- **[[sbi-feedback-model|โมเดล SBI]]** — โครงสร้างฟีดแบค 3 ส่วน (Situation–Behavior–Impact) ช่วยให้การ "Challenge Directly" เป็นรูปธรรมและไม่กล่าวโทษตัวบุคคล
- **[[feedforward-technique|เทคนิค Feedforward]]** (Marshall Goldsmith) — เสริม "Care Personally" ด้วยการโฟกัสที่อนาคตแทนการตอกย้ำอดีต

## ผลลัพธ์ของการใช้อย่างต่อเนื่อง

1. ผลงานดีขึ้น — พนักงานรู้ชัดว่าต้องปรับปรุงอะไร
2. ทีมกล้าแสดงความเห็นมากขึ้น — เพราะรู้สึกมีคุณค่าและปลอดภัย
3. พนักงานพัฒนาตนเองต่อเนื่อง — นำฟีดแบคไปปรับใช้และหาทางพัฒนาเอง (self-correction)

## บันทึกของ TK (มุมมอง Tech Lead)

กรอบนี้ใช้ได้ตรงกับงาน 1-on-1 และ retro ของทีม Data Engineering / AI Agent — โดยเฉพาะ Ruinous Empathy เป็นกับดักที่พบบ่อยเวลาฟีดแบคโค้ดรีวิวหรือ PR ของทีมที่สนิทกัน ลองใช้ [[SBI Feedback Model|SBI]] เป็น checklist ก่อนเขียนคอมเมนต์รีวิวที่ละเอียดอ่อน
