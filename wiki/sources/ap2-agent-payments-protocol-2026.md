## What is AP2?

**Agent Payments Protocol (AP2)** is an open protocol for the emerging **Agent Economy**. It enables secure, reliable, and interoperable agent commerce for developers, merchants, and the payments industry.

AP2 is available as an **extension for the open-source Agent2Agent (A2A) protocol** (<https://a2a-protocol.org/>), with more integrations in progress.

### The Core Problem

Today's payment systems assume a human is clicking "buy" on a trusted website. When an autonomous agent initiates payment, this assumption breaks, creating unresolved questions:

- **Authorization:** How to verify a user gave an agent authority for a specific purchase?
- **Authenticity:** How can a merchant be sure an agent's request reflects the user's true intent, without errors or AI "hallucinations"?
- **Accountability:** If a fraudulent transaction occurs, who is responsible — the user, agent developer, merchant, or issuer?

Without a common protocol, the ecosystem risks fragmentation into proprietary payment solutions that confuse users, cost merchants more, and burden financial institutions. AP2 provides a **common language** for any compliant agent to transact securely with any compliant merchant globally.

## Core Principles

| Principle | Description |
|---|---|
| **Openness & Interoperability** | Non-proprietary extension for A2A and MCP; any compliant agent works with any compliant merchant |
| **User Control & Privacy** | User is always the authority; privacy-centric role-based architecture; encryption protects sensitive data |
| **Verifiable Intent** | Trust anchored to deterministic, non-repudiable proof of user intent — not inferred action |
| **Clear Transaction Accountability** | Cryptographic audit trail for every transaction; supports dispute resolution and builds confidence |
| **Global & Future-Proof** | Initial version supports "pull" payments (credit/debit cards); roadmap covers "push" payments (UPI, PIX) and digital currencies |

## Verifiable Credentials (VCs) — The Trust Mechanism

AP2 engineers trust using **Verifiable Credentials** — tamper-evident, cryptographically signed digital objects that serve as transaction building blocks.

### Three Primary VC Types

| VC Type | Scenario | Generated By | Contains |
|---|---|---|---|
| **Intent Mandate** | Human **not** present | Shopping Agent (UA) | User's shopping constraints (budget, categories, TTL); authorizes agent to execute within bounds |
| **Cart Mandate** | Human **present** | Merchant Endpoint | Final itemized cart with exact products, price, destination; user's cryptographic signature provides **non-repudiable proof** |
| **Payment Mandate** | Both | Shopping Agent → Payment Network | Signals AI agent involvement + transaction modality (human-present vs. not-present) for risk assessment by network/issuer |

## Role-Based Architecture

| Role | Description |
|---|---|
| **User** | Individual delegating a payments task to an agent |
| **User Agent (UA) / Shopping Agent (SA)** | AI surface the user interacts with (Gemini, ChatGPT); understands needs, builds cart, gets user authorization |
| **Credentials Provider (CP)** | Specialized entity (digital wallet) securely managing payment credentials and methods |
| **Merchant Endpoint (ME)** | Agent/interface operating on behalf of merchant to showcase products, negotiate a cart |
| **Merchant Payment Processor (MPP)** | Constructs final transaction authorization message for the payment network |
| **Network & Issuer** | Payment network and financial institution that issued the user's payment credentials |

## Integration with the Protocol Stack

AP2 sits at **Layer 4** in the agentic commerce stack:

| Layer | Protocol | Purpose |
|---|---|---|
| L1 | **A2A** (Agent2Agent) | Agent-to-agent coordination, multi-agent collaboration |
| L2 | **MCP** (Model Context Protocol) | Agent-to-tools/data connections (context gathering) |
| L3 | **UCP** (Universal Commerce Protocol) | Commerce logic, merchant interactions, checkout sessions |
| L4 | **AP2** (Agent Payments Protocol) | Cryptographic payment authorization, multi-party settlement |

**AP2 specifics at L4:**
- Instrument negotiation: agents ↔ merchants exchange supported payment methods
- Cryptographic signatures authorize without exposing raw credentials
- Multi-party settlement (split payments across merchants)
- PCI-DSS compliance: keeps sensitive data in specialized processors

## The AP2 Promise

AP2 enables the full lifecycle:
1. Build agents with **ADK** (or any framework)
2. Equip with **MCP** (or any tool)
3. Collaborate via **A2A**
4. Secure payments with **AP2**

The vision: a world where AI agents can autonomously discover products, negotiate terms, and complete transactions — with cryptographic proof of user intent at every step.
